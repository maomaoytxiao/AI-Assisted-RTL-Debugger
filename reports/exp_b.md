## Failure
- **Test:** TEST 5 `underflow`
- **First failing check:** `count` — got `0xf`, expected `0x0` (also `empty` got `0x0`, expected `0x1` at the same time)
- **Timestamp:** 436000 ps (1 ns after the rising edge at 435000 ps)

Interpretation: the legal last read happens at 425000 (count 1 -> 0, rd_data 0x10). At 435000, with empty=1 and rd_fire=0, rd_ptr still moves 0000 -> 0001, so `count = wr_ptr - rd_ptr` wraps to 15 and `empty` drops. The DUT then "reads" stale storage (mem[1] = 0x0a at 445000), and `underflow` is no longer asserted.

## Suspected root cause

**File:** `build/debug/exp_b/rtl/sync_fifo.sv`, **line 71**, signal **`rd_ptr`**

```verilog
69:            if (rd_fire)
70:                rd_data <= mem[rd_ptr[AW-1:0]];
71:            if (rd_en)                       // <-- should be rd_fire
72:                rd_ptr  <= rd_ptr + 1'b1;
```

The read-pointer increment is gated by the raw request `rd_en` instead of the accepted-read qualifier `rd_fire = rd_en && !empty`. Reads while empty must be dropped (spec: "Read: accepted on a rising edge when `rd_en && !empty`"), but this code advances `rd_ptr` anyway, corrupting the pointer difference. Suggested fix: `if (rd_fire) rd_ptr <= rd_ptr + 1'b1;` (not simulated).

### Alternatives considered
- `count`/`empty` derivation wrong — rejected: they are correct for the observed pointers; the pointers themselves are wrong.
- `rd_fire` definition wrong — rejected: `rd_fire=0` with `rd_en=1, empty=1` at 434000, as specified.
- `rd_data` gating wrong — rejected: rd_data held 0x10 across the dropped read; data errors only follow the pointer corruption.
- Write-side bug — rejected: `wr_en=0`, `wr_ptr` constant; fill/drain/overflow tests passed.
- Testbench model error — rejected: the DUT's own `rd_fire`/`underflow` show the read was dropped, yet `rd_ptr` moved.
